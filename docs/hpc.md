# HPC と分散メモリ

MN-Core 2 で計算を速くするための考え方を、GPU との違いから簡単にまとめます。
用語は [用語集](terms.md) を参照してください。

## GPU と MN-Core 2 の違い

| | GPU | MN-Core 2 |
|---|---|---|
| キャッシュ | ある。よく使うデータはハードウェアが自動で近くに置く | ない。どのデータをどこに置くかは、すべて命令で指定する |
| 命令の流れ | 多数のスレッドが並行して進む | ボード全体で 1 本。すべての PE が同期して、同じ命令を実行する |
| 分岐 | 書ける | 命令の流れに分岐はない。マスクで条件を表す |
| メモリ | 大きな共有メモリを、多数の演算器から読み書きする | PE、L1B、L2B、グループがそれぞれ自分のメモリを持つ。メモリが階層ごと・場所ごとに分かれている（分散メモリ） |

## MN-Core 2 で速く処理するには

### 1. メモリの転送を少なくする

計算に使うデータを運ぶ回数を減らすことは、MN-Core 2 に限らず、GPU でも CPU でも速くするための基本です。
一度 PE まで運んだデータは、できるだけその場で何度も使います。

### 2. キャッシュがないことを前提に、データの置き場所を決める

MN-Core 2 にはキャッシュがないので、「よく使うデータが自動で近くに残る」ことはありません。
どのデータを、どのメモリ（PE メモリ、L1BM、L2BM、DRAM、PDM）に、いつ置くかを、プログラムで決めます。
そのかわり、置き場所と転送のタイミングを、すべて自分で制御できます。

### 3. PE を有効に使う

チップには 4096 個の PE があり、すべての PE が同じ命令を実行します。仕事のない PE があると、その分の
演算器が遊びます。すべての PE に仕事が行き渡るように、データを配ります。

### 4. 1 つの PE にいくつもの処理を入れる

扱うデータの数が PE の数（4096）を超えるときは、1 つの PE に複数のデータを受け持たせます。
PE メモリ（LM0 / LM1 は各 2 Ki u64、GRF0 / GRF1 は各 256 u64）の容量の範囲で、1 つの PE が順に
いくつものデータを処理します。逆に、データの数が 4096 より少ないと、使われない PE が出ます。

### 5. MN-Core 2 をたくさん使う

1 枚の MN-Core 2 で足りないときは、複数の MN-Core 2 に仕事を分けます。PFCP では、pod に割り当てる
MN-Core 2 の数を指定できます（[PFCP で使う](pfcp.md) の Deployment の `preferred.jp/mncore2`）。
ボードごとにメモリが分かれているので、ボードの間でデータを分け、必要なデータをやり取りする、
分散メモリの HPC と同じ組み立て方になります。
