# 用語集

このドキュメントで使う MN-Core 2 の用語です。定義は、PFN の「MN-Core 2 ソフトウェア開発者マニュアル」の
記述にもとづきます。

## チップの構成

| 用語 | 意味 |
|------|------|
| PE（Processing Element） | 演算の最小単位。PE メモリと ALU を持つ。プログラムカウンタや命令デコーダは持たない。チップ全体で 4096 個 |
| ALU（Arithmetic Logic Unit） | PE の中の演算ユニット |
| MAU（Matrix Arithmetic Unit） | 行列ベクトル積の専用の演算ユニット。MAB に 1 つあり、4 つの PE が共有する |
| MAB（Matrix Arithmetic Block） | PE 4 個と MAU 1 個からなるブロック |
| L1B（Level 1 Block） | MAB 16 個と L1BM からなるブロック |
| L2B（Level 2 Block） | L1B 8 個と L2BM からなるブロック。チップに 8 個 |
| トップレベル | チップの階層の根。PDM、DRAM、L2BM の間のデータ転送を行う |
| グループ | L2B 2 つずつの組。チップに 4 グループあり、グループごとに PDM と DRAM が 1 つずつ付く |

## メモリ

| 用語 | 意味 |
|------|------|
| PDM（PIU Data Memory） | グループごとの SRAM（4 MiB）。PIU は PCIe Interface Unit。ホストとの入出力は、すべて第 0 グループの PDM を経由する |
| DRAM | グループごとのメインメモリ（4 GiB） |
| L2BM（L2 Block Memory） | L2B ごとの SRAM（32 Ki u64） |
| L1BM（L1 Block Memory） | L1B ごとの SRAM（8 Ki u64） |
| PE メモリ | PE の中のメモリの総称。GRF0、GRF1、T レジスタ、LM0、LM1 |
| GRF0 / GRF1（General Register File） | PE の汎用レジスタファイル（各 256 u64） |
| LM0 / LM1（Local Memory） | PE のローカルメモリ（各 2 Ki u64） |
| T レジスタ（Temporary Register） | PE の一時レジスタ（8 u64） |
| マスクレジスタ | 書き込みを飛ばす、演算結果を 0 にする箇所を示すフラグを持つ特殊な PE メモリ。32 エントリ（15 エントリは書き換え可能） |

## 命令

| 用語 | 意味 |
|------|------|
| MV 命令 | PDM、DRAM、L2BM の間のデータ転送を行う命令。発行したあと、後に続く命令とは非同期に進む |
| PE 命令 | L2B より下（L2BM と L1B の間、L1BM と PE の間）のデータ転送と、PE・MAU の演算を行う命令。1 命令で 4 サイクル（1 ステップ）制御する |
| 命令ストリーム | ホストからボードへ送る 1 本の命令列。PE 命令と MV 命令を組にした単位の繰り返しでできている。分岐などの制御の構造はない |
| サイクル | クロックの 1 周期 |
| ステップ | PE 命令 1 つが制御する 4 サイクルの単位 |
| auto stride モード | 命令ストリームの形式の 1 つ。ステップの中で、サイクルごとにアドレスに一定の増分が加わる |
| flat モード | 命令ストリームの形式の 1 つ。GRF0、GRF1、LM0、LM1 のアドレスをサイクルごとに指定できる |
| wait | PE 命令に含める指定。指定した MV 命令が完了するまで、その PE 命令の発行を待たせる |

## 転送の操作

| 用語 | 英語 | 意味 |
|------|------|------|
| ブロードキャスト | broadcast | 同じデータを、下位の複数の宛先へ送る |
| リデュース | reduce | 下位の複数のデータを演算（和など）で 1 つにまとめて、上位へ送る |
| ディストリビュート | distribute | 上位のデータを等分して、下位の各宛先へ配る |
| コレクト | collect | 下位の各データを同じ大きさずつ読み出し、つなげて上位へ書く。ディストリビュートしたデータをそのままコレクトすると、元と同じ並びに戻る |
| ポイントツーポイント | point-to-point | 1 つの宛先へ個別に送る |

## 待ち（ハザード）

| 用語 | 意味 |
|------|------|
| ハザード | 命令の間に必要なステップ（サイクル）を空けないと、正しく動かない状況。アセンブラが検査し、違反するとエラーにする |
| データ競合 | 書き込みが終わるまで、同じアドレスの読み出しを待つ必要があることによるハザード |
| ポート衝突 | アドレスの信号線などのハードウェアが空くのを待つ必要があることによるハザード。アドレスによらず起こる |
| 書き込みマスク | マスクレジスタのフラグが 0 の箇所で、書き込みを行わないようにする指定 |
| ゼロフラッシュマスク | マスクレジスタのフラグが 0 の箇所で、演算結果を 0 にする指定 |

## データ

| 用語 | 意味 |
|------|------|
| u16 / u32 / u64 | データの幅（ビット数）の単位。それぞれ 16 / 32 / 64 ビット。型の名前ではない。容量も「8 Ki u64」のように、この単位で表す |
| fp64 | 64 ビットの浮動小数点数（符号 1、指数部 11、仮数部 52 ビット。IEEE 754 の binary64 と同じ配分） |
| fp32 | 32 ビットの浮動小数点数（符号 1、指数部 8、仮数部 23 ビット。IEEE 754 の binary32 と同じ配分） |
| E6M9 | 16 ビットの浮動小数点数（符号 1、指数部 6、仮数部 9 ビット）。IEEE 754 の binary16（指数部 5、仮数部 10）とは配分が違う。PFN の資料では「半精度」と呼んでいる |
| E8M18 | 指数部 8、仮数部 18 ビットの浮動小数点数。単独の値としては使わず、MAU のブロックフロートでだけ使う。PFN の資料では「疑似単精度」と呼んでいる |

**E6M9、E8M18 という名前について**: E のあとの数字が指数部のビット数、M のあとの数字が仮数部のビット数を
表す書き方（ExMy）です。業界標準の名前がない形式を、ビットの配分がわかるように呼ぶために使います。
この書き方は、NVIDIA・Arm・Intel の共著論文「FP8 Formats for Deep Learning」（2022 年、E4M3 と E5M2 を
定義。[arXiv:2209.05433](https://arxiv.org/abs/2209.05433)）にならっています。
| ブロックフロート | 複数の値をまとめたブロックの中で、指数部を 1 つだけ共有する浮動小数点数の形式。MAU の行列ベクトル積の入力に使う |
