# 37-bitonic-sort-8192: バイトニックソート（8192 個、f64）

8192 個の f64 の値を、値の番号の昇順に並べるバイトニックソートである。`36-bitonic-sort`（4096 個）の続きで、
**4096 個を超える個数でも `@get_hypercube_neighbor` が使える**ことを見せる。

## 8192 個を 4096 PE で扱う方法

1 チップの PE は 4096 個なので、**各 PE が 2 つの値を持つ**。値の番号を `i = j + 4096·r` とする（j は PE の番号、r は 0 か 1）。

| レジスタ | 値の番号 i | `@distribute size 2` で配られる成分 |
|---|---|---|
| A（`$lm0`） | j | 成分 0（PDM の前半 4096 個） |
| B（`$lm2`） | j + 4096 | 成分 1（PDM の後半 4096 個） |

PDM の並びは `[成分 0 を 4096 PE 分][成分 1]` なので、前半 4096 個が A、後半 4096 個が B になり、`@collect size 2` で戻すと、
値の番号 i の順に並ぶ。

`@get_hypercube_neighbor` の `<deep>` は 0〜11 だけである。8192 個の相手 `i XOR 2^j` は、j によって、次の 2 通りになる。

- **j が 0〜11 のとき:** 相手は、同じ r の値を持つ別の PE にある。`@get_hypercube_neighbor`（deep = j）を、A と B のそれぞれに
  1 回ずつ、**合わせて 2 回呼ぶ**。`<src_reg>` に `$lm0`（A）と `$lm2`（B）を、`<dest>` に別々のレジスタ（`$ls16` と `$ls18`）を書く
- **j が 12 のとき（段 13 の最初の 1 回だけ）:** 相手は、同じ PE のもう一方の値である。PE の間の移動は要らず、
  `<deep>` に 12 は書けないので、**レジスタの値の入れ替えを `dmin` / `dmax` で書く**（A が小さい方、B が大きい方）

16384 個以上も、2 の冪乗の個数なら、同じ考え方（各 PE が持つ値を増やし、`<deep>` が 12 以上の段はレジスタの入れ替えで書く）で
扱える。この example は 8192 個だけを作り、emu:lib と実機で動作を確かめてある。

## アルゴリズム

全体は 13 段で、13 × 14 / 2 = **91 ステップ**である（段 s は 1〜13、各段のステップ j は s−1 から 0）。
値 i は、相手 `i XOR 2^j` の値と比べ、i の bit j と bit s が等しければ小さい方、そうでなければ大きい方を新しい値にする
（bit s が 0 なら昇順、1 なら降順。s = 13 は、i の bit 13 が常に 0 なので、すべて昇順）。

i の bit s は、s によって取り出し方が変わる。

| s | i の bit s | 小さい方を取る条件（`t = PE の番号 & Mmask`） |
|---|---|---|
| 1〜11 | PE の番号 j の bit s（A も B も同じ） | `Mmask = 2^j + 2^s`、A も B も `t == 0` または `t == Mmask` |
| 12 | r（A は 0、B は 1） | `Mmask = 2^j`、A は `t == 0`、B は `t == 2^j` |
| 13 | 常に 0 | `Mmask = 2^j`、A も B も `t == 0` |

`lxor` で、条件に合う PE の `omr` が 1 になるようにし、最初に大きい方を置いたうえで、`maskr` でその PE にだけ小さい方を
上書きする（`36-bitonic-sort` と同じ作り方）。`gen_vsm.py` が、全 91 ステップの `_vsm` を作る（手で書かない）。

## 期待値

ホスト（`sort_host.c`）が、kernel と同じ規則で先頭の `<steps>` ステップを計算した配列（8192 個）を作り、kernel の結果と
**8192 個すべて**を、ビット列の完全一致で比べる。`<steps>` が 91 のときは、あわせて、結果が入力を昇順に並べたものと
一致することを確かめる。

入力は、-2^32 以上 2^32 未満の f64 の疑似乱数で、**有限で 0 でない値**（正と負の両方）である。`dmin` / `dmax` は、0 を同一視し、
NaN の扱いが特別なので、0 と NaN は入れない。

## 実行

```bash
ninja              # vsmlink のみ（全 91 ステップ）
ninja build-e2e    # + assemble3 + C ビルド
ninja test-emu-lib # emu:lib で 91 ステップを実行し、全体が昇順になることを確かめる（10 秒ほど）
ninja test-device  # 実機で 91 ステップを実行し、全体が昇順になることを確かめる
ninja verify       # 代表的なステップだけの版の vsmlink の出力と expected.vsm の diff
```

`expected.vsm` は、全体の出力が大きくなるので、代表的な 4 ステップ（(s=2, j=1)、(s=12, j=3)、(s=13, j=12)、(s=13, j=0)）だけの
ものである。j = 12 の入れ替えと、s = 12 と 13 の条件の違いが含まれる。

## PDM の配置（`sort8192.param`）

| slot | 用途 | `:addr`（u64） |
|---|---|---|
| 8 | PE の番号（`@identify`）、4096 個 | 0 |
| 16 | 入力（`@distribute size 2`）、8192 個 | 4096 |
| 24 | 出力（`@collect size 2`、`:recv_wait_tag` #x1e）、8192 個 | 16384 |
| `nbuf0` | `@get_hypercube_neighbor` の一時バッファ（deep 9〜11 で使う。4160 u64） | 32768 |
