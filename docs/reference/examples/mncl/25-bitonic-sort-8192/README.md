# 25-bitonic-sort-8192: バイトニックソート（8192 個、double）

8192 個の double を、要素の番号の昇順に並べるバイトニックソートである。`24-bitonic-sort`（4096 個）の続きで、
**4096 個を超える個数でも `get_hypercube_neighbor` が使える**ことを見せる（vsmlink の `37-bitonic-sort-8192` に当たる MNCL の example）。

## 8192 個を 4096 PE で扱う方法

1 チップの PE は 4096 個なので、**各 PE が 2 つの値を持つ**。要素の番号を `i = j + 4096 * r` とする（j は PE の番号、r は 0 か 1）。

| 変数 | 要素の番号 i | `distribute2` の成分 |
|---|---|---|
| `a` | j | 成分 0（入力の前半の 4096 個） |
| `b` | j + 4096 | 成分 1（入力の後半の 4096 個） |

PDM の並びは `[成分 0 を 4096 PE 分][成分 1]` なので、前半 4096 個が a、後半 4096 個が b になり、`collect2` で戻すと、要素の番号 i の順に並ぶ。

`get_hypercube_neighbor` の `deep` は 0〜11 だけである。8192 個の相手 `i XOR 2^j` は、j によって次の 2 通りになる。

- **j が 0〜11 のとき:** 相手は、同じ r の別の PE にある。a と b のそれぞれに `get_hypercube_neighbor` を 1 回ずつ（合わせて 2 回）呼ぶ。
  第 2 引数には**要素の番号**を渡す（a には `id`、b には `id + 4096`）
- **j が 12 のとき（段 13 の最初の 1 回だけ）:** 相手は、同じ PE のもう一方の値である。PE の間の移動は要らず、`deep` に 12 は書けないので、
  a と b を比べて、a に小さい方、b に大きい方を入れる

## 比較の向き

全体は 13 段で、13 × 14 / 2 = **91 ステップ**である（段 s は 1〜13、各段のステップ j は s−1 から 0）。
要素 i は、相手 `i XOR 2^j` と比べ、**i の** bit j と bit s が等しければ小さい方、そうでなければ大きい方を新しい値にする。
bit s は**要素の番号**の bit s である。

| s | i の bit s | a（i = id） | b（i = id + 4096） |
|---|---|---|---|
| 1〜11 | PE の番号 id の bit s | a と b で同じ向き | a と b で同じ向き |
| 12 | r（a は 0、b は 1） | 昇順 | **降順** |
| 13 | 常に 0 | 昇順 | 昇順 |

**b の向きを `id`（下位 12 ビットだけ）で決めると、段 12 で a と b が同じ向きに並び、段 13 のバイトニックマージの前提
（全体が一度増えて減る列になっていること）が成り立たず、整列しない。** `id_b = id + 4096` を使うのは、このため
（`get_hypercube_neighbor` は下位 12 ビットだけを見るので、`id_b` を渡しても相手の PE は変わらない）。

## ホストがすること（`test_bitonic-sort-8192.c`）

1. PE の番号 `[0..4095]` を `:identify` の番地（addr 0）へ送る
2. 入力 8192 個を `a`（slot 8）へ送る（前半 4096 個が各 PE の a、後半が b）
3. kernel を実行し、`out`（slot 16）の 8192 個を受け取る
4. 結果が、入力を `qsort` で昇順に並べたものと、ビット列まで一致することを確かめる

## PDM の配置（`bitonic-sort-8192.param`）

| slot | 用途 | `:addr`（u64） |
|---|---|---|
| `:identify` | PE の番号（4096 個） | 0 |
| 8 | 入力（8192 個。`:send_wait_tag` #x11） | 4096 |
| 16 | 出力（8192 個。`:recv_wait_tag` #x1e） | 16384 |
| `:buffer nbuf0` | 作業領域（4160 u64） | 32768 |

## 実行

```bash
ninja test-emu-lib # emu:lib で実行し、全体が昇順になることを確かめる
ninja test-device  # 実機で実行（実機で PASS を確認）
```

## 注意（同時に使う `long` の値の数）

同時に生きる `long`（i64）の値が多い（a の分と b の分の `id >> j`）。mncl-kit 0.3.5 の XREG は 32 本で、この example は 20 本以上が要る
（19 本では、レジスタが足りずにコンパイルの誤りで止まる）。
