# 68-dmwrite-dmread — MAB 内で PE 番号と語番号を交換する

行列レジスタを経由すると、MAB 内の 4 PE と各 PE の 4 語との間で添字が交換されます。

```
	dmwrite $lm0v $lx0
	nop/24
	dmread $lx0 $lm30v
```

## これは行列の転置ではありません

行列演算の機能ではありません。起きるのは 2 次元配列の添字の交換だけで、値が行列を
表しているかどうかとは関係がありません。dev manual も「出力において浮動小数点数と
解釈しての正規化などは行われず、ビット列としてコピーが行われる」と書いていて、u64
整数にもそのまま使えます。

`dmread` の dev manual での名称は「fp64 行列レジスタ転置読み出し」ですが、この
「転置」は行列としての転置演算という意味ではなく、書き込みと読み出しで行と列の対応が
入れ替わることを指しています。以下では manual の名称を引用する箇所を除いて、
**添字の交換**と書きます。

## 何が起きるか

s を MAB 内の PE 番号 (0..3)、c を語番号 (0..3) とします。

```
入力を A[s][c]、出力を B[s][c] と書くと    B[s][c] = A[c][s]
```

添字 s と c が交換されます。

## メモリ上でどこへ移るか

入力は LM0 の u32 アドレス 0, 2, 4, 6 の 4 語、出力は 30, 32, 34, 36 の 4 語です
(アドレスの単位は後述)。16 個の値がどこへ移るかを表にすると次のようになります。

| 入力の位置 | addr 0 | addr 2 | addr 4 | addr 6 |
|---|---|---|---|---|
| **PE0** | PE0 の addr 30 | PE1 の addr 30 | PE2 の addr 30 | PE3 の addr 30 |
| **PE1** | PE0 の addr 32 | PE1 の addr 32 | PE2 の addr 32 | PE3 の addr 32 |
| **PE2** | PE0 の addr 34 | PE1 の addr 34 | PE2 の addr 34 | PE3 の addr 34 |
| **PE3** | PE0 の addr 36 | PE1 の addr 36 | PE2 の addr 36 | PE3 の addr 36 |

表の見方は、入力側の **PE 番号がアドレスに変わり、アドレスが PE 番号に変わる**、
ということです。同じ PE の 4 語が 4 つの PE へ散り、逆に 4 つの PE の同じ位置の語が
1 つの PE に集まります。

PDM を経由したときに PDM 上の並びがどう変わるかは 69-dmwrite-dmread-pdm を参照して
ください。この example は PE のメモリを直接読み書きするので、PDM は登場しません。

## 行列レジスタとは

PE ではなく MAB が持つレジスタです。1 MAB につき 2 面あり、`$lx` と `$ly` で指定します。
本来は行列ベクトル積和演算のためのものですが、書き込みと読み出しを組み合わせると
添字の交換に使えます。

fp64 のとき、行列データは 4 行 4 列です。1 命令が 4 サイクル動くので、1 命令で
16 要素すべてを読み書きできます。

行列レジスタから転置を行わずに読み出す命令は存在しません。読み出せば必ず添字が
交換されます。

## なぜ添字が交換されるか

2 つの命令が、行列レジスタの行と列を逆の意味で使うためです。

**`dmwrite $lm0v $lx0`** — サイクル c では、MAB 内の 4 PE から第 c 語を 1 つずつ集め、
行列レジスタの**行 c** に横一列に並べます。PE 番号が列の位置になります。

| サイクル c の読み出し元 | 書き込み先 |
|---|---|
| PE0 の第 c 語 | 行 c の列 0 |
| PE1 の第 c 語 | 行 c の列 1 |
| PE2 の第 c 語 | 行 c の列 2 |
| PE3 の第 c 語 | 行 c の列 3 |

**`dmread $lx0 $lm30v`** — サイクル c では、行列レジスタの**列 c** を縦に読み、
行 i の値を PE i に配ります。行番号が PE 番号になります。

| サイクル c の読み出し元 | 書き込み先 |
|---|---|
| 行 0 の列 c | PE0 の第 c 語 |
| 行 1 の列 c | PE1 の第 c 語 |
| 行 2 の列 c | PE2 の第 c 語 |
| 行 3 の列 c | PE3 の第 c 語 |

書くときは「行 = 語番号、列 = PE 番号」、読むときは「行 = PE 番号、列 = 語番号」です。
この食い違いが添字の交換を生みます。式で書くと次のようになります。

```
dmwrite   行列レジスタ[c][s] = A[s][c]
dmread    B[s][c]            = 行列レジスタ[s][c]
合成      B[s][c]            = A[c][s]
```

dev manual の 3.6.10.1 (dmwrite) と 3.6.11.1 (dmread) の動作記述に対応します。

## 実測結果

MAB0 の 4 PE の LM0 先頭 4 語に、PE 番号と語番号が 16 進の桁で読める値
(PE s の 語 c = 0xA*sc*) を置いたときの 3 段階です。

**入力** — LM0 の u32 アドレス 0, 2, 4, 6

| | 語0 | 語1 | 語2 | 語3 |
|---|---|---|---|---|
| PE0 | a00 | a01 | a02 | a03 |
| PE1 | a10 | a11 | a12 | a13 |
| PE2 | a20 | a21 | a22 | a23 |
| PE3 | a30 | a31 | a32 | a33 |

**行列レジスタ `$lx`** — `dmwrite` の直後

| | 列0 | 列1 | 列2 | 列3 |
|---|---|---|---|---|
| 行0 | a00 | a10 | a20 | a30 |
| 行1 | a01 | a11 | a21 | a31 |
| 行2 | a02 | a12 | a22 | a32 |
| 行3 | a03 | a13 | a23 | a33 |

行 c に「全 PE の第 c 語」が並んでいます。列の位置が PE 番号です。

**出力** — LM0 の u32 アドレス 30, 32, 34, 36

| | 語0 | 語1 | 語2 | 語3 |
|---|---|---|---|---|
| PE0 | a00 | a10 | a20 | a30 |
| PE1 | a01 | a11 | a21 | a31 |
| PE2 | a02 | a12 | a22 | a32 |
| PE3 | a03 | a13 | a23 | a33 |

下 2 桁が入れ替わっています。行列レジスタの行 s の内容が、そのまま PE s の 4 語に
なっていることも読み取れます。

## MAB 内で閉じること

`ex_dm_swap.c` は MAB0 と MAB1 の両方に値を置きます。値は MAB 番号も桁に含めた
4 桁 (MAB m の PE s の 語 c = 0xA*msc*) にしてあります。

交換後は下 2 桁だけが入れ替わり、MAB の桁 (上から 2 桁目) は動きません。MAB1 の値が
MAB0 に現れることも、その逆も起きません。**4 PE を超える範囲の並び替えには使えない**
ということです。

## 2 つの vsm

| ファイル | 実行のしかた | 見えるもの |
|---|---|---|
| `data/dm_swap.vsm` | libmnc2 経由。`ninja test-emu-lib` | 入口と出口 |
| `data/dm_swap_dset.vsm` | `gpfn3_package_main` を手で実行 | 入口・出口に加えて行列レジスタの中身 |

行列レジスタの中身が libmnc2 経由で見えないのは、`mnc2_debug_read` が扱えるメモリ
領域 (`MNC2_MEM_PDM` / `DRAM` / `L2BM` / `L1BM` / `LM0` / `LM1` / `GRF0` / `GRF1`) に
行列レジスタが含まれないためです。上の実測結果の中段は `dm_swap_dset.vsm` の出力です。

`dm_swap_dset.vsm` が使う `d set` / `d get` は、エミュレータ実行時専用の制御文
(dev manual 3.4.3 / 3.4.4)。実機では実行できないので、この vsm は `.idma.dat` に
せず `.asm` のまま使います。

## 実行

libmnc2 経由 (期待値と比較して PASS / FAIL を出す):

```sh
ninja
ninja test-emu-lib
```

host 無しで手で確認する (行列レジスタの中身まで見える):

```sh
ninja
gpfn3_package_main -i _build/dm_swap_dset.asm
```

後者の出力は `DEBUG-LM0(...)` と `DEBUG-MRx(...)` の 36 行です。`v:0xA00` のように
値が読めます。上の実測結果の表はこの出力を並べ直したものです。

## アドレスの単位に注意

vsm のオペランドと host 側 API で単位が違います。

| | 単位 | 入力の位置 | 出力の位置 |
|---|---|---|---|
| vsm のオペランド | u32 (dev manual 3.2.1) | `$lm0v` = 0, 2, 4, 6 | `$lm30v` = 30, 32, 34, 36 |
| `mnc2_debug_read` / `mnc2_debug_write` の addr | u64 | 0, 1, 2, 3 | 15, 16, 17, 18 |

`$lm` は u64 アクセスなので、`v` (アドレスインクリメント) は u32 単位で 2 ずつ進みます。
`$lm30` は u32 アドレス 30 であり、u64 で数えると 15 番目になります。`ex_dm_swap.c`
が `mnc2_debug_read` に渡す addr が 15 なのはこのためです。

## 待ちサイクルについて

`nop/24` は安全側に倒したもので、必要量ではありません。

dev manual には行列レジスタ書き込みから転置読み出しまでのステップ数の規定がありません。
行列ベクトル積和演算については「行列レジスタに書き込んだ直後のステップから実行可能」
(3.6.1.14) と書かれていますが、転置読み出しには同じ記述がなく、ハザードを列挙した
3.6.3 節にも行列レジスタは含まれません。

実測では `nop` を 1 つも置かなくてもアセンブラは通り、エミュレータの結果も変わりません
でした。ただしエミュレータはサイクルアキュレートではなく任意の命令が発行後即時完了する
(3.4.3) ため、これは実機で待ちが不要である根拠にはなりません。

## backend

emu:lib のみ。`mnc2_debug_write` / `mnc2_debug_read` がエミュレータ専用 API で、
実機には対応する機構が無いためです。05-debug-read / 46-debug-write / 47-debug-read-write
と同じ扱いで、`build.ninja` に `test-emu` と `test-device` の target はありません。

3 backend すべてで走る形が必要なら 69-dmwrite-dmread-pdm を参照してください。PDM を
経由するので debug API を使わずに済みます。
