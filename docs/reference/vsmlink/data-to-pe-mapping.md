# データと PE の対応

PDM の上のデータを PE に配ったとき、**どの番号のデータがどの PE に入るか**は、配る directive によって違う。
隣の PE の値を受け取る `@get_neighbor` は、PE の位置で相手を選ぶ。そのため、配る directive の違いが
「隣の値が、データの何番か」の違いになって現れる。

この文書は、取り違えやすいこの関係を、例で順に示す。directive の構文と規則は
[`directives-spec.md`](directives-spec.md) を参照する。この文書は、その規則を言い換えるのではなく、
規則が何を意味するかを例で確かめるためのものである。

## 1. 2 つの言葉

この文書では、次の 2 つを区別して使う。

| 言葉 | 意味 |
|---|---|
| **PE の番号 j** | 4096 個の PE に付いた 0〜4095 の番号。`@get_neighbor` の右隣（`+1`）は PE j+1、左隣（`-1`）は PE j−1 |
| **データの番号 k** | PDM の上に並べたデータの何番目か（0 から数える）。`.param` の slot が指す `:addr` から数える |

「PE j の隣」は PE の番号で決まる。「データ k の隣」は、データの番号で決まる。
**この 2 つが同じになるかどうかは、データを配る directive で決まる。** 同じになるとは限らない。

## 2. 先に結論

- `@get_neighbor` が選ぶのは、**PE の番号**で決まる相手の PE である。受け取る値は、その相手の PE の
  `<src_reg>` に**いまある値**である
- `@get_neighbor` は、その値がどの slot から来たか、データの番号が何番かを**知らず、検査もしない**
- `@distribute` で配った値では、PE の隣とデータの隣が一致する（データ k は PE k）
- `@distribute_aos2soa` で配った値では、PE の隣とデータの隣は**一致しない**（データ k は PE
  `4 * (k % 1024) + k / 1024`）
- `@distribute_aos2soa` で配った値に `@get_neighbor` を使っても、**エラーにならず動く**。ただし、受け取るのは
  番号の隣のデータではない
- どのレジスタにどのデータが入っているか、それが隣の計算に使ってよいものかは、**使う側が管理する**

## 3. どの PE にどのデータが入るか

### `@distribute`（転置なし）

データ k は PE k に入る。

| データの番号 k | 入る PE の番号 j |
|---|---|
| 0 | 0 |
| 1 | 1 |
| 2 | 2 |
| 3 | 3 |
| 4 | 4 |
| 1023 | 1023 |
| 1024 | 1024 |
| 4095 | 4095 |

### `@distribute_aos2soa`

データ 1 個は連続 4 u64 の値で、PDM に番号の順に並ぶ。配ると、データ k は PE
`4 * (k % 1024) + k / 1024` に入る（`/` は小数点以下を切り捨てる整数の割り算）。データ 1 個の 4 個の値は、
その PE の 4 本のレジスタに、値 0、1、2、3 の順で入る。

| データの番号 k | 入る PE の番号 j |
|---|---|
| 0 | 0 |
| 1 | 4 |
| 2 | 8 |
| 3 | 12 |
| 1023 | 4092 |
| 1024 | 1 |
| 1025 | 5 |
| 2048 | 2 |
| 3072 | 3 |
| 4095 | 4095 |

**番号の隣（k と k+1）が、PE では 4 つ離れている**（データ 0 は PE 0、データ 1 は PE 4）。
逆に、**PE の隣（PE 0 と PE 1）は、番号では 1024 離れている**（PE 0 はデータ 0、PE 1 はデータ 1024）。

使うデータが 4096 個より少ないときも、入る PE は上の式で決まる。先頭の PE 0〜N−1 に詰まって入るわけではない。

## 4. 例 1: `@distribute` で配った値の右隣

データ 0〜4095 を `@distribute` で配り、`@get_neighbor` で右隣（`+1`）を受け取る。

| 受け取る PE | その PE が持つデータの番号 | 右隣の PE | 受け取るデータの番号 |
|---|---|---|---|
| PE 0 | 0 | PE 1 | 1 |
| PE 1 | 1 | PE 2 | 2 |
| PE 2 | 2 | PE 3 | 3 |
| PE 4095 | 4095 | （端） | 端の指定で決まる値（[`directives-spec.md`](directives-spec.md) の「端の指定」） |

**PE の右隣のデータは、番号の右隣である。** 1 次元の格子の計算（差分、ステンシル）で、普通に期待する動作になる。

## 5. 例 2: `@distribute_aos2soa` で配った値の右隣

データ 0〜4095 を `@distribute_aos2soa` で配り、同じように `@get_neighbor` で右隣（`+1`）を受け取る。

| 受け取る PE | その PE が持つデータの番号 | 右隣の PE | 受け取るデータの番号 |
|---|---|---|---|
| PE 0 | 0 | PE 1 | **1024** |
| PE 1 | 1024 | PE 2 | **2048** |
| PE 2 | 2048 | PE 3 | **3072** |
| PE 3 | 3072 | PE 4 | **1** |
| PE 4 | 1 | PE 5 | 1025 |

**データ 0 が受け取るのは、データ 1 ではなく、データ 1024 である。** `@get_neighbor` は PE の番号で相手を選ぶだけで、
データの番号は見ないためである。エラーにも警告にもならない。

## 6. 例 3: 取り違えたときに起きること

次のように考えて書くと、結果が合わない。

> 「データ k の右隣はデータ k+1 のはずだ。`@distribute_aos2soa` で配ったのだから、`@get_neighbor` で
> データ k+1 の値が取れる」

- データ k+1 は PE k+1 にはない（例: データ 1 は PE 4）。`@get_neighbor` は PE の右隣（PE j+1）を取るので、
  データ k+1 とは別の値を受け取る
- エラーにならないので、値が合わないことに気づきにくい
- 番号の隣のデータが必要な計算では、**`@distribute` で配る**。または、配るときの対応を、使う側が自分で計算に入れる

## 7. 責任の範囲

| 項目 | `@get_neighbor` | 使う側（MNCL・利用者）|
|---|---|---|
| 相手の PE を、PE の番号で選ぶ | する | |
| 相手の PE の `<src_reg>` の値を受け取る | する | |
| レジスタが、どの slot のデータを持っているか | 見ない | 管理する |
| その値が、隣の計算に使ってよいものか | 検査しない | 管理する |
| データの番号と PE の対応 | 見ない | 配る directive に合わせて管理する |

`<src_reg>` に何が入っているかは、`@get_neighbor` からは見えない。`@distribute` で配った値でも、
`@distribute_aos2soa` で配った値でも、計算の途中の値でも、同じように受け取る。

## 8. よくある取り違え

**Q1. `@get_neighbor` は、どの slot のデータを隣として取るかを知っているのか。**
知らない。`<src_reg>` で指定したレジスタの、隣の PE にいまある値を取るだけである。slot とレジスタの
結びつきは、使う側が保つ。

**Q2. `@distribute_aos2soa` で配った値には、`@get_neighbor` を使えないのか。**
使える。エラーにならず動く。ただし、受け取る値は番号の隣のデータではない（例 2）。

**Q3. 隣の PE の値とは、配った元の値のことか。**
そうとは限らない。`@get_neighbor` を実行した時点で、隣の PE の `<src_reg>` にある値である。配った値を
書き換えていれば、書き換えた後の値を受け取る。

**Q4. `@collect_soa2aos` で書けば、PDM の並びは番号の順に戻るのか。**
`@distribute_aos2soa` で配った値を、PE を変えずに `@collect_soa2aos` で書けば、PDM の並びは配る前と同じになる
（`directives-spec.md` の「対で使うと元に戻る」）。転置の無い `@distribute` で配った値を `@collect_soa2aos`
で書いても、番号の順にはならない。

**Q5. 同じ kernel で `@distribute` と `@distribute_aos2soa` の両方を使ってよいか。**
使える。ただし、PDM の上では、片方は PE の順、片方は番号の順に並ぶ。値を読むときは、どちらで書いたものかを
取り違えない。

**Q6. 4096 個を超えるデータでも、`@get_neighbor` は隣を受け取れるか。**
1 つのチャンク（4096 個）の中の隣だけを扱う。チャンクの端の PE（境界のフラグに cross_chip か data_edge が立っている PE）が受け取る値は、端の指定で決まる。
隣のチャンクの値が要るときは、その値を端の PE のレジスタに置き、`:reg <register>` で渡す（[`directives-spec.md`](directives-spec.md) の「端の指定」）。

## 9. 使い分け

- 番号の隣のデータが欲しい計算（格子の隣、1 次元の並びの隣）には、転置の無い `@distribute` / `@collect` を使う
- `@distribute_aos2soa` / `@collect_soa2aos` は、PDM の上でデータ 1 個分（4 個の値）ずつを番号の順に置いたまま、
  PE の側では成分ごとに持たせたいときに使う。PE の番号に意味のある計算には使わない
- 迷ったときは、**データ 0 と、その右隣のデータ 1 が、どの PE に入るか**を、この文書の表で確かめる。
  隣り合う PE（PE j と PE j+1）に入るなら、`@get_neighbor` で番号の隣が取れる
