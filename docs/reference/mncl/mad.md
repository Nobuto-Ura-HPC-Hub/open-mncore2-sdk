# `mad` — f64 の積和と、MN-Core 2 の丸め

`mad(a, b, c)` は `a * b + c` を、MN-Core 2 の積和命令（`dvfmau` / `dvfmad`）で計算する。
**結果は、正確に丸めた積和（OpenCL の `fma()`）と一致しない場合がある。** この文書は、API と、その理由（MN-Core 2 の動き）を説明する。
`api-reference.md` から参照される。

## API

```c
double mad(double a, double b, double c);   // a * b + c
```

| 項目 | 内容 |
|---|---|
| 型 | `double`（f64）のスカラだけ。`float`、`doubleN`（ベクタ）は対応していない（コンパイルの誤りで止まる） |
| 値 | `a * b + c`。`a * b` の途中の値は、`double` に丸めない（下の「計算」） |
| 符号反転 | `mad(a, b, -c)`（`a*b - c`）は書ける |
| `fma()` | **対応していない**。呼ぶとコンパイルの誤りで止まる（理由は下の「`fma` と `mad` の違い」） |
| `a * b + c` と書いたとき | 乗算と加算の 2 つの演算のまま（`mad` にはならない）。結果はこれまでと変わらない |

呼び出しは、ふつうの関数のように書く。OpenCL C の標準関数 `mad` に当たる。

## `fma` と `mad` の違い（この API を `mad` にした理由）

- OpenCL の `fma(a, b, c)` は、`a * b` を厳密に計算して `c` を足し、**丸めを 1 回だけ**行った値を返すと定められている。
- OpenCL の `mad(a, b, c)` は、`a * b + c` を計算するが、**中間の丸めと精度は実装に任される**。
- MN-Core 2 の f64 の積和は、下に書く通り、正確に丸めた積和とは一致しない場合がある。そのため、定義の合う `mad` の名前で提供する。
  `fma()` の名前で提供すると、OpenCL の定義（正確な丸め）に反する値を返すことがある。

## MN-Core 2 の動き（dev manual 4.3 節）

**f64 のベクトル積和は、仮数部の下位 16 ビット同士の部分積を省略し、補正項 2^-74 で置き換える。**

`a * b` の仮数部は、a と b の仮数部（52 ビット）の積である。MN-Core 2 は、この積のうち、a の下位 16 ビットと b の下位 16 ビットを掛けた部分を計算しない。
代わりに、次の補正項を加える。

| 省略した部分の積の和 | 補正項 |
|---|---|
| 0 | 0 |
| 0 以外 | 2^-74（省略した仮数部の最上位にだけ 1 が立っていた場合と同じ結果） |

そのあとの手順は、次の通りである（dev manual 4.3）。

1. `c` を、積との指数の差の分だけずらし、仮数部の長さを無限として加算する
2. 出力（f64）の仮数部の長さへ、**最近接偶数丸めで 1 回だけ**丸める。繰り上がりで指数が変わることがある
3. 指数が無限大や 0 の範囲に入るときは、対応する値にする
4. 正規化して出力にする

### どのくらいの違いか

- 省略した部分は、積の最上位の桁から **74 − 52 = 22 ビット**以上下の桁にある。出力の仮数部の長さよりずっと下にあるので、dev manual は「実用上ほとんどの場合に問題にならない」としている。
- **違いが出るのは、大きな桁落ちが起きるとき**である（`a * b` と `c` がほぼ打ち消し合い、下の桁の結果がそのまま出力に現れる場合）。
  dev manual の例は fp32 のもので、fp64 の実例は dev manual に無い。
- 乗算だけ（`a * b`）にも、同じ部分積の省略がある（MN-Core 2 の f64 の乗算は、積和の `c` を 0 にしたもの）。この点は、`mad` に限った性質ではない。

### 書き方への影響

- **積の丸め誤差を取り出す書き方（`fma(a, b, -a*b)` など）は、`mad` では正しい値にならない。** 正確な丸めを前提にした数値計算の技法は使えない。
- 結果が、numpy などの正確な丸めの積和と、ビット単位で一致しない場合がある。比べるときは、誤差の上限を決めて比べる
  （`share/examples/mncl/26-fft-4096` は、ノルム誤差で比べている）。
- コンパイラは、`mad` の呼び出しを定数として計算せず、引数がすべて定数でも命令にする。コンパイル時の値とデバイスの値が食い違うことはない。

## 命令の数

f64 の積和は、1 つの命令では全 PE の分を計算できない。`dvfmau`（PE0、PE1 の積を計算）と `dvfmad`（PE2、PE3 の積を計算し、前の結果を `$mauf` で通す）の
2 つを、間に何も挟まずに続けて出す。

| 書き方 | 命令の数（f64） |
|---|---|
| `a * b + c` | 3 つ（乗算 2 つ + 加算 1 つ） |
| `mad(a, b, c)` | 2 つ |

利用者は、この 2 つの命令の並びを意識しなくてよい。コンパイラが出す。

## 入力 3 つの置き場所

積和の入力 `a`、`b`、`c` は、別々のメモリ（GRF0、GRF1、LM0、LM1 のうち 3 つ）にある必要がある。同じメモリから 2 つの入力は読めない。
置き場所は、コンパイラが決める。利用者は指定しなくてよい。入力が別々のメモリにないときは、コンパイラがコピーの命令（`lpassa`）を足して置き直す
（同じ値を 3 つの入力に渡す `mad(x, x, x)` も書ける）。コピーの分だけ命令が増え、待ちも入る。

## 例: 複素数の乗算

複素数 `(dr, di)` と `(wr, wi)` の積 `(pr, pi)` は、次のように書ける。

```c
double t1 = di * wi;
double pr = mad(dr, wr, -t1);     // dr*wr - di*wi
double t2 = di * wr;
double pi = mad(dr, wi, t2);      // dr*wi + di*wr
```

4 つの実数の積と 2 つの加減算が、乗算 2 つと `mad` 2 つになる。FFT での使い方は `share/examples/mncl/26-fft-4096`
（vsmlink の `40-fft-4096` に当たる）を参照。
