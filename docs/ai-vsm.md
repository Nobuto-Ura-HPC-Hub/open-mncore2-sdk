# AI を使ったアプローチ（vsm 編）

**このページと、ここで挙げる資料を AI に読み込ませれば、AI が MN-Core 2 のプログラム（vsm と
ホストの C プログラム）を書けるはずです。**

このページでは、何を読み込ませ、どう頼めばよいかを紹介します。用語は [用語集](terms.md) を参照してください。

## vsm とは何か、どうやって使うか

vsm は、MN-Core 2 のアセンブリ言語です（拡張子 `.vsm`）。アセンブラ（`assemble3`）で、ボードに送る
命令列にします。

**vsm だけでは動きません。** 命令列をボードに送り、データを送受信し、実行するホストのプログラムが
必要です。この SDK では、ホストの C プログラムから **libmnc2** を使います。つまり、MN-Core 2 の
プログラムは **vsm + libmnc2（ホストの C プログラム）** の組で作ります。

| 作るもの | 役割 |
|----------|------|
| vsm（`.vsm`） | MN-Core 2 の上で実行する計算（kernel）。データの転送と演算を、命令で書く |
| ホストの C プログラム（libmnc2） | デバイスを開く、kernel の命令列を読み込む、データを送る、kernel を実行する、結果を受け取る |

libmnc2 は、同じコードのまま、実行先をエミュレータ（手元の PC）と実機（PFCP）で切り替えられます。
PFCP で実機を使うなら、SDK を入れたコンテナイメージ（ECR）から pod を作れます。使い方は
[PFCP で使う](pfcp.md) を参照してください。

いちばん小さな例は、libmnc2 のサンプル `01-nop` です（`sdk-examples libmnc2` でコピーできます）。
`data/nop.vsm` は何もしない kernel（`nop`）で、`ex_nop.c` はデータを送って、kernel を実行し、
受け取ったデータを比べるホストの C プログラムです。

## AI に読み込ませるもの

| # | 資料 | 入手先 | 読み込ませる理由 |
|---|------|--------|------------------|
| 1 | MN-Core 2 ソフトウェア開発者マニュアル（PFN） | [PDF](https://projects.preferred.jp/mn-core/assets/mncore2_dev_manual_ja.pdf)（[PFN の MN-Core のページ](https://projects.preferred.jp/mn-core/) の資料欄に最新版がある） | 命令、オペランド、ハザードなど、ISA の一次資料 |
| 2 | MN-Core Challenge の資料（PFN） | [公式サイト](https://mncore-challenge.preferred.jp/)（練習問題）、[Tips 集](https://mncore-challenge.preferred.jp/tips/) | 開発者マニュアルに書かれていない情報がある。MN-Core Challenge は、PFN が 2024 年に開いた、MN-Core 2 のアセンブリ言語のプログラミングコンテスト |
| 3 | この SDK の libmnc2-kit（説明書、ヘッダ、サンプル） | [GitHub Releases](https://github.com/Nobuto-Ura-HPC-Hub/open-mncore2-sdk/releases) の `libmnc2-kit-*.tar.gz` | ホストの C プログラムの書き方 |

3 の libmnc2 の説明書は、このサイトの [リファレンス](reference/README.md) でも読めます。ただ、AI に
読み込ませるなら、`libmnc2-kit-*.tar.gz` を取ってきて手元に展開し、中身（`share/` の説明書、
`include/` のヘッダ、`share/examples/` のサンプル）をすべて読み込ませるのが手軽です。

**本家の API について**: PFN（本家）は、ホストの側の API として libgpfn3 などを用意しています。
この SDK では、その上に作った libmnc2 を使っています。本家の API を使いたい場合は、そのマニュアルなども
AI に読み込ませる必要があります。

## 頼み方

「vsm とホストの C プログラムを書いて」とだけ頼んでも、うまくいきません。何をどう計算するかの設計が
ないからです。次の順に進めます。

1. **何を計算するかを決める**: 入力、出力、データの大きさ（要素の数、型）。
2. **設計を決める**: データを PE にどう配るか（1 つの PE がいくつの要素を受け持つか）、どのメモリ
   （DRAM、L2BM、L1BM、PE メモリ）に置くか、結果をどう集めて返すか。vsm の概要
   （[MN-Core 2 とは](mncore2.md)、[MN-Core 2 に合わせたプログラムの作り方](programming.md) くらい）を
   知っていれば、AI と相談しながら決められます。
3. **設計を伝えて書かせる**: 決めた設計を AI に伝えて、vsm とホストの C プログラムを書かせます。
   libmnc2 の細かい使い方は知らなくてかまいません。ホストの C プログラムは AI が書きます。
4. **試行錯誤させる**: アセンブラのエラー（ハザードの検査など）や、エミュレータ・実機での実行結果を
   見せながら、AI に直させます。

good luck!!

## 開発者マニュアルの用語について

PFN の開発者マニュアルには、1990 年代（あるいはそれ以前のメインフレームや初期の RISC・ベクトル計算機の
時代）の、JIS 規格をもとにした訳語が多く使われています。AI に読み込ませるときは、マニュアルを
テキストにして、今の用語に置き換えておくと扱いやすくなります（置き換えは各自で行ってください）。

また、マニュアルの「方向」という言葉は、PFN の中で使われているローカルな用語のようで、いくつかの
意味で使われています。置き換えるときは、意味ごとに言葉を分けます。

このドキュメントでは、次のように置き換えた言葉を使っています。

| 何の言葉か | 開発者マニュアル | 置き換え |
|------------|------------------|----------|
| データの幅 | 長語・単語・半語 | u64 / u32 / u16 |
| 浮動小数点数の名前 | 倍精度・単精度・半精度・疑似単精度 | fp64 / fp32 / E6M9 / E8M18 |
| 転送の操作 | 放送・縮約・分配・結合・個別 | ブロードキャスト・リデュース・ディストリビュート・コレクト・ポイントツーポイント |

「方向」は、意味ごとに次のように置き換えます。「〜軸」のような別のラベルに置き換えるのではなく、
何をしているかを具体的に書きます。

| 「方向」の意味 | 開発者マニュアルの例 | 置き換えの例 |
|----------------|----------------------|--------------|
| どの範囲にわたってまとめるか（リデュースなど） | 「L2B 方向に縮約」「グループ方向に縮約」「MAB 方向には縮約、PE 方向には結合」 | 「そのグループの 2 個の L2BM から読んでリデュースし」「グループをまたいでリデュースする」「PE の位置ごとに、16 個の MAB にわたってリデュースして」 |
| 転送の向き | 「L1BM -> PE 方向転送」「転送方向」（表の列） | 「L1BM -> PE 転送」「転送元 -> 転送先」 |
| マスクのビットの割り当て | 「サイクル方向」「ワード方向」 | 「1 ステップを構成する 4 サイクルそれぞれに 4 ビットずつ」「各サイクル分の 4 ビット」 |
| 順番 | 「L2B 通し番号方向にラウンドロビン」 | 「L2B 通し番号順にラウンドロビン」 |
| 丸めの向き | 「マイナス無限大方向に行う」「ゼロ方向に行う」 | 「負の無限大へ行う」「0 へ行う」 |
| 添字 | 「i 方向の加算」 | 「i を添字とする加算」 |
